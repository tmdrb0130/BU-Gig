# 백석대학교 긱창업

React 프론트엔드와 NestJS·TypeScript·PostgreSQL 백엔드입니다. 현재 기본 진입점은 `frontend/src/live/App.jsx`이며 실제 API를 사용합니다. 기존 데모 코드와 예시 데이터는 참고용으로 남아 있지만 실행 경로에서 가져오지 않습니다.

## 실행

백엔드 터미널:

```powershell
cd C:\Users\dltmd\Desktop\bu-cmong\backend
npm ci
npm run migrate
npm run dev
```

프론트엔드 터미널:

```powershell
cd C:\Users\dltmd\Desktop\bu-cmong\frontend
npm ci
npm run dev
```

`http://127.0.0.1:5173`으로 접속합니다. Vite가 `/api`를 `127.0.0.1:3000`으로 프록시합니다. 다른 API 서버는 `API_PROXY_TARGET`, 별도 공개 API 주소는 빌드 환경의 `VITE_API_BASE`로 지정합니다. 후자의 경우 서버 Origin과 쿠키 정책도 일치해야 합니다. 운영은 같은 Origin의 `/api` reverse proxy와 SPA fallback을 권장합니다.

**기존 서버는 종료 후 재시작하세요.** 로컬 PGlite는 한 프로세스만 DB를 열 수 있으므로 실행 중 별도 migrate/seed/staff 명령을 실행하지 않습니다. 이번 변경은 `004_home_review_opt_in.sql`과 `005_notification_preferences.sql`을 추가합니다. 실제 운영 데이터에는 `seed:dev`를 실행하지 않습니다. 예전에 seed한 데이터는 자동 삭제하지 않으므로 빈 출시 검증에는 별도 빈 DB를 사용하세요.

## 운영 노출 정책

| 항목 | 표시 기준 |
| --- | --- |
| 홈 후기 | 공개 완료 거래에서 의뢰인이 수행자에게 작성한 공개 후기, 작성자의 홈 노출 동의, 양쪽 계정 활성 상태. 서로 다른 거래 3건 이상일 때 최근 최대 4건 노출. 미달이면 섹션 전체 숨김 |
| 후기 작성 | 완료 거래 당사자만 작성. 실제 별점 사용. 홈 노출 동의는 기본 해제. 작성자는 공개/비공개 변경 가능 |
| 평점·후기 수 | 서버의 공개 후기 집계. 0건이면 별점 대신 '아직 받은 후기가 없어요' |
| 학교 인증 | 서버 VERIFIED 상태이며 유효기간 내인 경우만 배지 표시. 미인증·만료·해제는 인증으로 표시하지 않음 |
| 완료 실적 | 서버의 실제 완료 거래 집계. 등록한 포트폴리오 개수로 대체하지 않음 |
| 검증된 작업물 | 완료 거래 및 해당 버전의 공개 승인 확인. 일반 작업물 등록만으로 인증 부여하지 않음 |
| 인기 | 실제 찜 수로 정렬. 고정 인기 배지·가상 순위 없음 |
| 전문가 공개 | 소개 문구와 활동 분야 입력 후 본인이 공개 설정. 대표 작업물은 본인의 공개 작업물 최대 3개 선택 |
| 데이터 없음 | 빈 상태와 첫 행동 안내. 누락 작성자·아바타는 중립 표시. 통신 장애는 오류·재시도 표시 |

홈 후기에는 이름·학과·비공개 프로젝트 제목을 임의로 붙이지 않습니다. 예시 회원·실적·후기로 빈 화면을 채우지 않습니다.

## 실제 이용 흐름

1. 가입·로그인 → 필수 동의 → 프로필 설정. 이메일 확인과 학교 인증은 별개입니다.
2. 학교 증빙 제출 → 권한 있는 운영자의 심사·승인. 담당자는 `backend/README.md`의 staff 권한 부여 절차로 지정합니다.
3. 의뢰 초안 저장 → 게시 → 다른 인증 회원 지원 → 의뢰인 선정 → 실제 워크룸 생성.
4. 계약 검토 요청 → 양쪽 당사자의 동일 버전 동의 → 작업·메시지·파일 공유.
5. 수행자의 완료 요청 → 의뢰인의 승인 → 후기 작성. 결과물 공개는 별도 승인 흐름입니다.

지정 요청·견적 변경·수락, 계약 수정, 완료 보완 요청, 상호 취소, 찜, 알림, 작업물 공개 승인도 실제 API에 연결했습니다. 계정 데이터는 서버 세션 기준이며 계정 전환·로그아웃 시 이전 조회 화면을 초기화합니다. 자동 임시저장이 아닌 명시적 초안 저장입니다.

주요 경로: `/my`, `/my/profile`, `/my/verification`, `/my/portfolios`, `/my/publication-requests`, `/request/new`, `/projects/:id/apply`, `/my/projects/:id`, `/direct-requests/:id`, `/workrooms/:id`, `/admin`. `/workrooms`는 본인의 워크룸 목록입니다.

## 샘플 디자인 복원 및 기능 보완

`frontend/sample`과 UI/UX 문서의 색상·헤더·히어로·일러스트·탐색 카드·필터 구성을 실제 API 화면에 반영했습니다. 기존 데모 저장소를 실행 경로에 연결하지 않습니다.

- 탐색: 분야 다중 선택 메가메뉴, 적용/취소, 예산·기간 범위, 기술·평점 필터, 선택 칩, 최근 열람 항목, 찜, 페이지 이동. 모바일 필터는 하단 패널과 키보드 포커스 순환을 제공합니다.
- 상세: 의뢰 조건·첨부·지원 상태별 버튼, 전문가 대표 작업물·경력·서비스·후기, 작업물 이미지 갤러리, 모바일 지원 버튼, 실제 문의 대화.
- 작성: 4단계 의뢰/지정 요청, 서버 초안, 첨부와 미리보기, 미저장 이탈 확인. 지원서 첨부·수정 및 지원자 2~3명 비교를 제공합니다.
- 회원: 프로필 완성도·분야/기술·경력/서비스 편집, 마이페이지 활동 요약, 작업물 등록/수정·미리보기·파일 순서·대표작 선택·수정본 공개.
- 협업: 워크룸 진행 단계·탭·대화·계약·파일·완료, `/messages` 계정별 대화 목록, `/support` 문의/답변, `/my/reports` 신고 처리 상태.
- 설정/운영: `/settings/account` 계정 변경·탈퇴·알림 설정, 운영자 문의 답변·신고 처리·목록 페이지 이동. 메시지·신규 지원/요청 알림을 꺼도 필수 계약 알림과 SSE 데이터 갱신은 유지합니다.

## 검증

```powershell
# backend
npm run build
npm test
npm run openapi

# frontend
npm run build
npm test
npm run test:e2e
```

브라우저 테스트는 별도 메모리 DB와 3021/5179 포트에서 실행하므로 개발 DB를 사용하지 않습니다. 로컬은 Microsoft Edge, CI는 Playwright Chromium을 사용합니다. 가입·증빙 심사/해제·첫 의뢰부터 후기까지의 두 계정 거래·계정 전환·세션 만료·잘못된 수신자·빈 데이터/장애·모바일 화면을 검증합니다. 백엔드 테스트에는 홈 후기 0→3건 노출/철회와 인증 만료도 포함합니다. 기존 `tests/e2e`와 `test:e2e:demo`는 과거 데모 전용이며 현재 화면의 통과 기준이 아닙니다. `npm test`는 기존 필터 유틸리티 회귀 검사입니다.

## 배포 전 실제 설정

- 정식 이용약관·개인정보 처리방침을 게시하고 `TERMS_URL`, `PRIVACY_URL`, `TERMS_VERSION`, `PRIVACY_VERSION`을 설정합니다. hosted 환경에서는 누락 시 신규 가입을 차단합니다.
- OAuth 버튼은 설정된 공급자만 표시합니다. 제공자 앱·callback URI와 실서비스 계정 검증은 별도로 필요합니다.
- 개발 메일은 `backend/.data/mail` 파일로 기록합니다. 운영 SMTP 발송, S3, clamd, 외부 PostgreSQL, HTTPS는 실제 환경에서 검증해야 합니다.
- 결제·정산과 자동 배포는 이번 범위에 포함하지 않습니다. 운영 화면은 인증 심사·문의 답변·신고 처리·작업 재시도·감사 조회를 지원합니다. 자유형 포트폴리오 블록 편집기, 운영 콘텐츠 CMS·계정 제재 관리 화면은 제공하지 않습니다. 대표작 선택과 공개 승인 등 일부 보조 목록은 최대 50건 범위이므로 대규모 운영 전 목록 탐색을 확장해야 합니다.
