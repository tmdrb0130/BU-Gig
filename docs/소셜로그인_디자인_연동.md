# 로그인 시안·소셜 버튼 적용 기록

기준일: 2026-09-30. 사용자 제공 `frontend/sample/로그인.png`를 로그인·회원가입·재설정 화면의 시각 기준으로 반영했다. 별도 브랜드 헤더, 중앙 카드, 옅은 배경, 보조 푸터를 사용하며 일반 탐색 헤더와 모바일 하단 내비게이션은 인증 화면에서 제외한다.

## 공식 디자인 기준

- 카카오: 노란 배경 `#FEE500`, 공식 심볼과 지정 레이블을 유지. ‘카카오로 시작하기’ 대신 제공 자산의 **카카오 로그인**을 사용한다. 로고를 일반 채팅 아이콘으로 대체하지 않는다. [공식 디자인 가이드](https://developers.kakao.com/docs/ko/kakaologin/design-guide)
- 네이버: 현재 가이드의 지정 녹색 **`#03A94D`**와 흰색 로고/레이블을 사용한다. 완성형 로고 최소 크기·여백·원래 비율을 보존한다. 시안의 밝은 녹색을 그대로 복제하지 않는다. [공식 버튼 가이드](https://developers.naver.com/docs/login/bi/bi.md)
- 두 버튼은 동일한 전체 폭·56px 높이로 표시. 내부 공식 이미지는 종횡비를 유지하며 수평 여백만 컨테이너로 채운다. 작은 화면에서도 글자/심볼을 찌그러뜨리거나 N 로고를 글꼴 문자로 재작성하지 않는다. PNG 원본에 포함된 외곽 여백은 좁은 컨테이너에서 잘릴 수 있으나 로고·레이블 영역은 보존한다.

| `frontend/public/brand/kakao-login.svg` | [카카오 리소스](https://developers.kakao.com/tool/resource/login)의 [완성형 SVG](https://developers.kakao.com/tool/images/resource/preview/login-complete-ko.svg) | 원본 파일, 비율 유지 |

로고 권리는 각 제공자에게 있으며 브랜드 가이드 변경 시 재검토한다. 공식 승인을 받았다고 표시하지 않는다.

## 현재 실제 동작

- 인증 헤더는 홈으로 이동하는 로고만 남기고 오른쪽 ‘홈으로 돌아가기’ 링크는 제거했다.
- 카드 상단의 영문 학교명은 제거하고 로그인/회원가입 제목과 설명만 표시한다.
- 로그인·회원가입은 같은 카드 너비(최대 500px), 화면별 내부 여백, 입력/버튼 높이와 제목 규격을 공유한다. 회원가입은 추가 필드 때문에 세로로 늘어나며 페이지 스크롤을 허용한다.
- 로그인은 노트북에서 푸터를 제외한 기본 카드가 한 화면에 들어오도록 높이에 따라 여백·간격을 조정한다. 회원가입 긴 폼, 오류/안내 펼침, 모바일 키보드·확대 상태에서는 정상 스크롤을 허용하며 내용을 숨기거나 화면 스케일을 강제로 축소하지 않는다.

- 이메일 가입/로그인은 기존 브라우저 데모를 유지한다.
- 로그인 상태 유지 체크는 명시적 opt-in, 기본 해제. 선택 시 `bu-gig:demo-remembered-session`에 ID·7일 만료 시각을 로컬 저장한다. 원문 암호는 저장하지 않으며 로그아웃 때 삭제한다. 운영 세션으로 사용하면 안 된다.
- 카카오/네이버는 **버튼 UI만 반영**했다. 클릭하면 연동 준비 안내를 표시하며 외부 인증·계정 생성·학교 인증이 수행되지 않는다.
- 필수 안내·계정 저장 동의는 데모용이다. 정식 약관/개인정보 처리방침은 준비 전이라는 안내를 제공하며 법률 문서를 임의로 확정하지 않는다.
- 시안의 학교명/인증 문구는 실제 허용 학교 범위가 미정이므로 ‘학교 구성원 인증’으로 표현한다. 별도 학교 인증 없이 전체 이용이 승인되었다고 표시하지 않는다.

## 백엔드 후속 설계

소셜 인증은 서버에서 인가 코드 교환·사용자 식별·서비스 세션 발급으로 연결한다. 제공자 설정/필수 파라미터는 구현 시 공식 문서로 재확인한다. [카카오 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api), [네이버 개발 가이드](https://developers.naver.com/docs/login/devguide/devguide.md)

프로젝트 설계 제안:

1. 앱 등록·허용 웹 origin·정확한 redirect URI·동의항목·검수 여부 준비. client secret은 프론트 bundle/VITE 변수에 넣지 않는다.
2. 서버가 생성한 일회용 state를 세션에 연결·만료·대조하고 callback 재사용을 차단한다. 제공자가 지원하는 PKCE/OIDC 사용 여부는 별도 확인한다.
3. `oauth_identities(user_id, provider, provider_subject)` 추가, `(provider, provider_subject)` unique. 이메일 문자열 일치만으로 기존 계정을 자동 병합하지 않는다. 연결은 기존 계정 재인증 후 수행한다.
4. 소셜 전용 계정의 비밀번호는 nullable이며 비밀번호 로그인 허용 여부를 구분한다. 학교 인증은 별도 단계다.
5. 제안 경로: `/api/v1/auth/oauth/:provider/start`, `/callback`, `/me/identities`. 마지막 로그인 수단 해제는 대체 인증 수단 확인 전 금지.
6. 사용자 동의 취소·제공자 오류·이미 연결된 계정·미제공 이메일·state 만료를 UI 상태로 제공한다. 성공 시 자체 세션을 발급하고 허용 내부 경로로만 복귀.
7. 제공자 토큰은 필요한 경우에만 서버 암호화 저장하고 로그에서 제거. 서비스 로그아웃과 제공자 연결 해제/탈퇴를 구분.

운영 승인 사항: 앱 소유자, 제공자별 동의항목, 연결/해제 정책, 검수 완료, 실제 가입 가능한 학교 범위. 현재 UI 반영만으로 소셜 로그인 구현이 완료된 것은 아니다.
