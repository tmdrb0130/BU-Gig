# 백석대학교 긱창업 플랫폼 UI·UX 디자인 가이드

> 목적: 숨고·크몽·Fiverr·Upwork·Contra 등 실제 매칭/프리랜서 플랫폼의 UX 패턴을 참고하여,  
> **백석대학교 구성원이 쉽고 빠르게 의뢰하고, 수행자는 자신의 실력과 결과물을 매력적으로 보여줄 수 있는 화면 구조**를 정의한다.
>
> **디자인 기준 최신화: 2026-09-30** — 확정된 홈 / 프로젝트 탐색 / 전문가 탐색 시안, Hover 필터, 간소화된 탐색 카드, 텍스트 중심 프로젝트 상세 원칙을 반영한다.

## 0. v2 최신 결정과 구현 구분

2026-09-30 프론트 구현 대조 개정. [구현 현황](README.md), [전체 아키텍처](시스템_아키텍처.md), [데이터·API](데이터_API_계약.md), [검증 계획](개발_검증_계획.md)을 함께 읽는다. 본문의 추천 화면은 모두 구현 완료된 화면을 뜻하지 않는다.

### 헤더와 인증 화면

- 넓은 화면: 로고 / 일 찾기 / 전문가 찾기 / 작업물 둘러보기 / 이용안내 / 검색 / 계정 도구 / 의뢰 등록.
- 검색은 기본 돋보기, 호버·클릭·키보드 포커스로 확장. 검색어가 있거나 입력 중이면 유지, 빈 값이며 호버·포커스 모두 해제되면 축소.
- 검색창은 이용안내 오른쪽 약 30px 간격부터 남은 도구 영역을 사용한다. 고정 최대 폭 때문에 불필요한 빈 공간을 남기지 않고 주변 메뉴를 밀지 않는다.
- 화면 폭 <768px 또는 확보된 검색 슬롯 <240px이면 헤더 전체를 `뒤로가기 / 검색 입력 / 지우기 / 검색`으로 전환한다. 이 수치는 현재 구현 기준이며 실제 글꼴·언어·기기 검증으로 조정 가능하다.
- 태블릿은 실제 공간이 충분하면 인라인 검색을 유지한다. 현재 768~1050px에서는 주 메뉴를 햄버거로 이동해 검색 공간을 확보한다.
- 모바일 일반 헤더: `로고 → 검색 → 의뢰 등록 → ☰`. 의뢰 등록은 메뉴 안에만 숨기지 않는다. 로그인/가입은 햄버거와 MY에서 접근.
- 로그인·회원가입은 `frontend/sample/로그인.png` 기준의 브랜드 헤더·중앙 카드·보조 푸터로 반영했다. 카카오/네이버 버튼은 공식 자산을 사용하며 OAuth는 미연결이다. 출처·색상·세션 유지 범위는 [적용 기록](소셜로그인_디자인_연동.md)을 따른다.

### 탐색 필터 확정 규칙

- 카테고리와 세부분야 버튼을 나누지 않는다. 일 찾기는 ‘카테고리 선택’, 전문가 찾기는 ‘전문 분야 선택’ 한 패널에서 대분류·세부분야를 고른다.
- 서로 다른 분야도 복수 선택 가능. 디자인 전체 + 개발·IT의 프론트엔드/백엔드를 동시에 선택할 수 있다. 분야 내 OR, 서로 다른 필터 축은 AND.
- 왼쪽 대분류 클릭은 탐색만 수행. 실제 선택은 ‘분야 전체’ 또는 세부분야 체크박스로 한다. 전체 선택은 해당 하위 선택을 포괄한다.
- 체크 시 패널을 닫지 않는다. 초안 선택·개수·결과 수를 확인하고 ‘결과 보기’로 확정. 취소/바깥 클릭/Escape는 미적용 변경을 버린다.
- 선택을 편집한 후 우연히 다른 버튼에 호버해도 현재 패널을 유지한다. 명시적으로 다른 필터를 클릭하면 전환 가능.
- 일반 드롭다운은 해당 버튼 바로 아래에 정렬하고 컨테이너 밖으로 넘치지 않게 보정. 분야 메가 메뉴는 넓은 패널을 사용하며 화면 경계에 맞춰 정렬한다.
- 필터는 ‘빠른 조건’ 제목·구분선·분리 그룹 없이 같은 간격으로 연속 배치. 마감 임박/현재 의뢰 가능/학교 인증은 뒤쪽 토글, 하위 패널 없음.
- 예산은 프리셋 및 최소/최대 직접 입력. 한쪽만 입력 허용, 원 단위·쉼표 표시, 역전/잘못된 숫자 오류 안내.
- 후기 필터는 `4.5점 이상 / 4.0점 이상 / 3.5점 이상`.
- 기간 직접 입력·기술 자동완성/분야 추천/다중선택·진행 방식 다중선택은 후속 설계이며 현재 적용된 기능으로 표시하지 않는다.

### 디자인 대기와 추가 상태

- **포트폴리오 등록/수정은 사용자 디자인 대기.** 8장의 입력/미리보기 예시는 이전 참고안이지 승인 시안이 아니다. 임의로 편집기 화면을 확정하지 않는다.
- 내 프로필 편집, 받은 지원·선정, 받은 지정 요청, 대화 목록, 계약 버전/동의, 완료·후기, 학교 인증, 설정, 운영 화면은 별도 설계/구현이 필요하다.
- 모든 서버 연동 화면은 로딩·빈 결과·검증 오류·통신 실패·세션 만료·권한 없음·삭제/비공개·동시 수정 충돌 상태를 포함한다.
- 계약 UI는 ‘열람’, ‘한쪽 동의’, ‘같은 버전 양측 체결’, ‘변경 검토본’, ‘PDF 생성 중’을 구분한다. 결제 완료를 표시하지 않는다.
- 운영에서 데모 이미지의 인증 배지·후기·완료 수치를 실제 사용자 신뢰 정보로 재사용하지 않는다.

### 구현 토큰과 참고 토큰

현재 CSS 기준: Primary `#0962ee`, Navy `#073584`, 본문 `#14213e`, Border `#e6ebf2`, 기본 radius 12px, Noto Sans KR/system fallback. 17장의 대학 색상·Pretendard 권장은 초기 참고안이다. 브랜드 승인 전 ‘공식 대학 색상 준수 완료’로 해석하지 않는다. 현재 헤더 최대 폭은 1440px이며 페이지별 본문 폭은 다르다.

## 1. 디자인 핵심 방향

### 한 문장 정의

**“학교 게시판 같은 외형이 아니라, 작업물을 먼저 보여주는 젊고 깔끔한 포트폴리오형 매칭 플랫폼.”**

### 가장 중요한 UX 원칙

1. **화면 목적에 따라 정보 우선순위를 다르게 한다.**
   - 전문가/포트폴리오: 글보다 대표 작업물을 먼저 보여준다.
   - 전문가 탐색에서는 프로필 사진보다 포트폴리오 썸네일의 비중을 높인다.
   - 프로젝트 탐색/상세: 이미지보다 `업무 내용·보상·기간·마감·결과물`을 먼저 보여준다.
   - 프로젝트 등록자에게 대표 이미지 제작을 요구하지 않는다.

2. **프로필 하나만 잘 만들면 계속 재사용할 수 있어야 한다.**
   - 프로젝트 지원 시 경력과 작업물을 다시 업로드하지 않는다.
   - 기존 포트폴리오에서 대표작 1~3개를 선택해 제안서에 첨부한다.

3. **처음 쓰는 학생도 어렵지 않아야 한다.**
   - 전문 용어 대신 일상적인 문구를 사용한다.
   - 긴 입력 폼 대신 단계형 입력과 선택형 칩을 적극 사용한다.
   - 프로필 완성도와 다음 할 일을 화면에서 바로 안내한다.

4. **의뢰자는 10초 안에 ‘이 사람이 뭘 잘하는지’ 판단할 수 있어야 한다.**
   - 프로필 첫 화면에서 전문 분야, 대표작, 기술, 완료 작업, 후기, 응답 상태를 확인할 수 있게 한다.

5. **매칭 후에는 기능이 흩어지지 않아야 한다.**
   - 채팅, 계약, 파일, 진행 상태를 하나의 `프로젝트 워크룸`에서 관리한다.

6. **모바일에서 먼저 이해되는 구조로 만든다.**
   - 학생 사용 비중을 고려하여 탐색·포트폴리오 열람·채팅·지원은 모바일에서 특히 단순하게 구성한다.

## 2. 상용 플랫폼에서 가져올 UX 패턴

| 플랫폼 | 강점 | 긱창업에 적용할 부분 |
|---|---|---|
| 숨고 | 요청서 작성과 전문가 직접 탐색의 두 경로가 명확함 | 홈에서 `의뢰 등록`과 `전문가 찾기`를 같은 비중으로 제공 |
| 숨고 | 작업 결과물, 작업 방식, 전후 이미지 중심 포트폴리오 | 사진·영상 중심 포트폴리오 및 Before/After 표현 |
| 크몽 | 포트폴리오가 검색결과, 상세, 프로필 등 여러 화면에 반복 노출됨 | 작업물을 별도 부가 정보가 아니라 탐색의 핵심 콘텐츠로 사용 |
| 크몽 | 서비스/전문가 카드에서 문의·찜으로 바로 연결 | 카드 → 프로필 → 문의까지 클릭 수 최소화 |
| Fiverr | 서비스 자체를 이미지 중심 카드로 상품처럼 이해시킴 | `제공 가능한 작업`을 프로필 안에서 시각적 카드로 제공 |
| Fiverr | 완료 작업과 직접 등록한 포트폴리오를 함께 활용 | 긱창업 완료 프로젝트를 검증 포트폴리오로 연결 |
| Upwork | 기술, 경력, 포트폴리오, 작업 이력을 한 프로필에 통합 | 프로필을 수행자의 통합 경력 페이지로 구성 |
| Upwork | 제안과 관련된 경력·작업물이 중요 | 제안서에서 기존 대표작을 선택하여 첨부 |
| Contra | 포트폴리오 자체가 개인 웹사이트처럼 아름답고 공유 가능 | 공개 프로필을 `한 링크 포트폴리오`처럼 디자인 |
| Contra | 서비스·작업·추천·계약이 한 사용자 흐름에 연결됨 | 보여주기 → 문의 → 프로젝트 → 계약의 흐름을 끊지 않음 |

### 디자인 참고 우선순위

```text
포트폴리오 감성 / 프로필 표현       → Contra
작업물 카드 / 서비스 탐색           → 크몽 + Fiverr
쉬운 요청 / 전문가 찾기             → 숨고
경력·기술·신뢰 정보                 → Upwork
학교 인증 / 교내 신뢰 장치          → 긱창업 자체 설계
```

## 3. 정보 구조

### 데스크톱 상단 내비게이션

```text
[긱창업 LOGO]  일 찾기  전문가 찾기  작업물 둘러보기  [통합검색........]
                                               채팅  알림  프로필
                                      [ + 의뢰 등록 ]
```

- 메뉴는 4~5개 이상 늘리지 않는다.
- `의뢰 등록`은 항상 눈에 띄는 Primary CTA로 둔다.
- 사용자가 수행자/의뢰자 모드를 별도로 전환하지 않아도 된다.

### 모바일 하단 내비게이션

```text
홈     탐색     + 의뢰     채팅     MY
```

`탐색` 안에서 다음을 탭으로 전환한다.

```text
프로젝트 | 전문가 | 작업물
```

## 4. 메인 홈 화면

### 목표

처음 방문한 사용자가 세 가지 행동 중 하나를 바로 시작하게 한다.

- 프로젝트를 찾는다
- 전문가를 찾는다
- 작업물을 둘러본다

의뢰자는 상단의 `+ 의뢰 등록` CTA로 바로 프로젝트 등록을 시작할 수 있다.

### 확정 레이아웃 방향

```text
Header
→ Hero + 브랜드 이미지/캠퍼스 감성
→ 중앙 통합 검색
→ 인기 키워드
→ 주요 카테고리
→ 지금 눈에 띄는 작업물
→ 이런 전문가가 있어요
→ 새로 올라온 의뢰
→ 전문가 탐색 유도 Banner
→ 후기/신뢰 콘텐츠
→ Footer
```

### Header

```text
[긱창업 Logo]  일 찾기  전문가 찾기  작업물 둘러보기  이용안내
                         [통합검색]
                                  알림  프로필  [+ 의뢰 등록]
```

규칙:

- 메뉴는 4개 중심
- 현재 메뉴 Underline/Active 표시
- `+ 의뢰 등록`은 항상 Primary CTA
- 프로젝트/전문가 모드 전환 기능을 따로 만들지 않음
- 헤더 높이와 구조는 탐색/상세 페이지에서도 동일하게 유지

### Hero

- 백석대학교 브랜드 감성은 사용하되 대학 홈페이지처럼 보이지 않게 구성
- 인물/캠퍼스 이미지는 Home Hero에서만 적극 사용 가능
- 큰 카피 + 짧은 설명
- 검색창은 Hero 하단 또는 경계부에 배치하여 탐색 행동으로 자연스럽게 연결

예:

```text
같은 학교의
실력 있는 사람에게
필요한 일을 맡겨보세요.

[ 어떤 프로젝트를 의뢰하고 싶으신가요?       검색하기 ]
```

### 통합 검색

검색 대상:

- 프로젝트
- 전문가
- 작업물
- 기술/키워드

추천 키워드는 Chip 형태로 5~8개 정도만 표시.

### 카테고리

한 줄 아이콘 메뉴:

```text
전체보기 / 디자인 / 개발·IT / 영상·사진 / 마케팅 /
문서·번역 / 기획·컨설팅 / 학습·과외 / 행사·운영 / 기타
```

너무 많은 세부 카테고리는 홈에서 펼치지 않는다.

### `지금 눈에 띄는 작업물`

- 이미지 중심
- 4열 정도
- 카드 클릭 → 포트폴리오 상세
- 이미지, 제목, 수행자/분야, 최소 반응 정보만 표시
- 긴 설명 금지

### `이런 전문가가 있어요`

- 대표 포트폴리오 이미지가 가장 큰 시각 요소
- 이름, 전문분야, 핵심 태그, 평점/완료 작업 정도
- Home에서는 전문가 탐색 페이지 카드보다 정보량을 더 줄임

### `새로 올라온 의뢰`

- 프로젝트 탐색 카드의 compact 버전
- 카테고리 / 제목 / 예산 / 마감 / 요약 / 지원 CTA
- 대표 이미지는 선택적

### 하단 Banner

목적:

`작업물을 보는 중 → 전문가 찾기` 행동으로 연결.

과도한 광고 배너처럼 보이지 않게 Home Hero와 같은 브랜드 톤을 재사용한다.

### 후기 영역

- 실제 완료 프로젝트 기반 후기만 노출
- 사용자 이름/소속은 개인정보 정책 범위 내
- 후기 카드는 짧게
- 평균 평점 수치를 과도하게 강조하지 않음

### 홈에서 피해야 할 것

- 학교 홈페이지처럼 긴 공지 배너가 첫 화면 대부분을 차지
- 모든 기능을 Home에 몰아넣기
- 세부 카테고리를 전부 펼치기
- 통계 숫자를 핵심 콘텐츠보다 먼저 노출
- 전문가 카드와 프로젝트 카드의 정보량을 탐색 페이지 수준으로 과하게 표시
- 서로 다른 카드에 동일한 Primary CTA가 너무 많이 반복되어 화면이 파랗게 보이게 만들기

## 5. 탐색 화면

프로젝트 탐색과 전문가 탐색은 **같은 검색 경험을 학습할 수 있도록 거의 동일한 레이아웃**을 사용한다.

다른 것은 결과 카드의 판단 정보다.

```text
프로젝트 탐색
→ 무슨 일 / 보상 / 기간 / 마감 중심

전문가 탐색
→ 대표 작업 / 분야 / 평점 / 완료 경험 중심
```

### 5.0 공통 탐색 Shell

```text
Header
Breadcrumb
H1 + 짧은 설명
가로 Filter Bar
선택된 Filter Chips
결과 수 + 정렬
─────────────────────────────
결과 목록              보조 Sidebar
```

데스크톱 콘텐츠 최대 폭은 약 `1200~1280px`.

보조 Sidebar는 탐색을 방해하지 않게 좁게 유지하고 다음 정도만 제공한다.

- 인기 검색어/분야
- 최근 본 프로젝트/전문가
- 검색 도움말

### Filter Bar 공통 스타일

- 흰 배경
- Border 중심
- Radius 10~12px
- Outline Icon + Label + Chevron
- Active 필터만 Blue Border/Text
- `필터 초기화`는 버튼군 오른쪽
- 화면 폭이 부족하면 일부 필터를 `기타 조건`에 넣거나 가로 스크롤

## 5.1 프로젝트 탐색

### 화면 목적

수행자가 **내가 할 수 있는 일 / 받을 보상 / 일정 가능 여부**를 빠르게 판단한다.

### 상단 카피

```text
지금, 함께할 프로젝트를 찾아보세요
백석대학교 구성원의 다양한 프로젝트가 기다리고 있어요.
```

### 필터

권장:

```text
[카테고리 선택] [예산] [기간] [진행 방식] [필요 기술]
[마감 임박 토글] [학교 인증 토글] [초기화]
```

### Hover/Click Mega Menu

`카테고리 선택`에 Hover 또는 Click 시 버튼 바로 아래에 Mega Menu가 열린다.

```text
┌────────────┬──────────────┬──────────────┬──────────────┬────────────┐
│ 전체       │ 로고·브랜딩  │ 그래픽 디자인 │ 공간·제품     │ 기타 디자인 │
│ 디자인     │ 로고 디자인  │ 상세페이지     │ 인테리어      │ 캘리그라피   │
│ 영상/사진  │ 브랜드 가이드│ SNS 디자인     │ 제품·굿즈     │ 타이포그래피 │
│ 개발       │ 포스터·인쇄물│ PPT            │ 3D 모델링     │ 전시·무대    │
│ ...        │ ...          │ 웹·앱 UI/UX    │ ...          │ ...         │
└────────────┴──────────────┴──────────────┴──────────────┴────────────┘
```

Interaction:

- 대분류 Hover → 우측 세부 카테고리 갱신
- 대분류 Click → 우측 항목 탐색, 전체/세부 체크박스로 실제 선택
- 세부 항목 Click → 초안 다중선택 유지, 결과 보기에서 적용
- 편집 전 다른 필터 Hover로 전환 가능, 편집 후 명시적 Click으로 전환
- 패널 바깥 Click / `Esc` → 닫기
- Hover 기능은 Click/Keyboard로도 동일하게 접근 가능
- 버튼과 패널 사이에 Pointer Gap 때문에 메뉴가 닫히지 않게 구현

### 적용 필터

```text
프로젝트 42건
[서울 전체 ×] [디자인 ×] [예산 10~50만원 ×] [+ 필터 추가]   [최신순 ▾]
```

### 프로젝트 카드 — 확정 방향

```text
┌──────────┬───────────────────────────────┬─────────────────────────┐
│ 썸네일    │ [디자인]                       │ ₩ 100,000원   7일   D-5 │
│           │ 학교 행사 포스터 디자인        │                         │
│           │ 설명 최대 2줄                  │ 이지현 · ✓ 백석대 인증   │
│           │ #포스터 #그래픽디자인 #일러스트 │              [지원하기] │
└──────────┴───────────────────────────────┴─────────────────────────┘
```

규칙:

- 썸네일은 사용자가 반드시 올리는 이미지가 아님
- 첨부 이미지가 없으면 Category Placeholder
- 카테고리 Badge는 작은 크기
- 제목이 가장 강한 타이포
- 설명 최대 2줄
- 태그 최대 3개
- 금액 / 기간 / 마감은 오른쪽에서 즉시 스캔 가능
- 마감 D-day만 필요한 경우 Warning 색
- 의뢰자 프로필 사진은 생략 가능
- 찜은 오른쪽 상단
- 카드 전체 Click → 프로젝트 상세
- `지원하기` → 지원/견적 작성
- 정보 밀도를 늘리기 위해 카드 높이를 과하게 키우지 않음

## 5.2 전문가 탐색

### 화면 목적

의뢰자가 **이 사람이 어떤 결과물을 만들 수 있고 신뢰할 수 있는지** 빠르게 판단한다.

### 상단 카피

```text
지금, 함께할 전문가를 찾아보세요
백석대학교 구성원의 뛰어난 전문가들을 만나보세요.
```

### 필터

```text
[전문 분야 선택] [기술] [후기] [완료 프로젝트]
[현재 의뢰 가능 토글] [학교 인증 토글] [초기화]
```

프로젝트 탐색과 동일한 Mega Menu/Dropdown Interaction을 그대로 재사용한다.

### 적용 필터

```text
전문가 42명
[디자인 전체 ×] [후기 4.5 이상 ×]  [리뷰 많은순 ▾]
```

### 전문가 카드 — 확정 방향

프로필 사진을 크게 보여주지 않는다.

```text
┌────────────┬──────────────────────────────────────────────┐
│ 대표 작업물 │ [디자인]                                      ♡│
│ 이미지      │ 김서연 | 브랜드·그래픽 디자이너               │
│            │ 브랜드의 가치를 시각적으로 표현하는 디자이너입니다│
│            │ #브랜딩 #포스터 #로고디자인                    │
│            │ ★4.9(32) · 작업 28건 · 평균 2시간 내 응답       │
│            │ ✓ 백석대 인증                     [프로필 보기] │
└────────────┴──────────────────────────────────────────────┘
```

규칙:

- 대표 포트폴리오 이미지가 주 시각 요소
- 프로필 사진은 목록에서 생략 가능
- 이름 + 전문 분야를 같은 행에 자연스럽게 배치
- 설명 최대 1~2줄
- 기술/업무 태그 최대 3개
- 평점/완료/응답은 한 줄의 Secondary 정보
- 학교 인증은 작은 Badge
- `현재 의뢰 가능`은 필요 시 Success Badge
- Primary CTA는 `프로필 보기`
- 카드 전체 Click → 공개 프로필

### 프로젝트 탐색과 전문가 탐색의 공통성

다음은 반드시 동일 Component를 쓴다.

- Header
- Page Title spacing
- Filter Button
- Mega Menu
- Filter Chip
- Sort Dropdown
- Result List Container
- Sidebar
- Empty State
- Pagination / Infinite Pagination 정책
- Skeleton

사용자가 `일 찾기 ↔ 전문가 찾기`를 이동했을 때 새로운 사이트처럼 느껴지면 안 된다.

## 10. 제공 가능한 작업

전문가가 “무슨 일을 받을 수 있는지”를 명확하게 표현하는 가벼운 서비스 카드다.

크몽처럼 복잡한 판매 상품/옵션 구조까지 만들지 않는다.

예:

```text
┌────────────────────────┐
│ 웹 UI/UX 디자인         │
│ 랜딩페이지·서비스 화면  │
│ 예상 기간 3~7일         │
│ 금액: 협의              │
│             [문의하기]  │
└────────────────────────┘
```

필드:

- 서비스명
- 한 줄 설명
- 카테고리
- 관련 기술
- 예상 기간
- 예상 금액 또는 협의
- 관련 포트폴리오 연결

최대 3~5개 정도만 등록하도록 제한한다.

## 11. 프로젝트 상세

### 핵심 정의

프로젝트 상세는 **의뢰자가 예쁘게 꾸미는 판매 페이지가 아니라, 수행자가 업무 조건을 명확히 확인하는 프로젝트 공고 상세**다.

따라서 전문가 공개 프로필/포트폴리오 상세과 정보 우선순위가 다르다.

```text
전문가/포트폴리오 상세
→ 이미지와 결과물 중심

프로젝트 상세
→ 텍스트, 보상, 기간, 산출물, 요구사항 중심
```

숨고처럼 등록 부담은 낮게 유지하고, 크몽처럼 업무 범위와 조건은 구조화하여 보여주는 방향을 사용한다.

### 사용자가 첫 10초에 확인해야 하는 것

```text
무슨 일인가?
보상은 얼마인가?
언제까지인가?
무엇을 만들어야 하는가?
내 기술이 맞는가?
지금 지원할 수 있는가?
```

### 데스크톱 전체 구조

```text
┌─────────────────────────────────────────────┬──────────────────────┐
│ Breadcrumb                                  │ 모집중       D-5     │
│ [디자인] [포스터/인쇄물]                    │                      │
│                                             │ 예산                 │
│ 학교 행사 포스터 디자인                     │ 100,000원            │
│ 짧은 프로젝트 요약                          │                      │
│ ✓ 백석대 인증 의뢰자 · 2시간 전             │ [지원하기]           │
│ #포스터 #그래픽디자인 #Illustrator           │ [문의하기]           │
│                                             │ [♡ 프로젝트 저장]    │
│ ────────────────────────────────────────── │                      │
│                                             │ ✓ 학교 인증 의뢰자   │
│ 한눈에 보는 프로젝트                        │                      │
│                                             │                      │
│ 프로젝트 내용                               │                      │
│                                             │                      │
│ 원하는 결과물                               │                      │
│                                             │                      │
│ 작업 요청사항                               │                      │
│                                             │                      │
│ 필요한 기술 및 도구                         │                      │
│                                             │                      │
│ 일정 안내                                   │                      │

│                                             │                      │

└─────────────────────────────────────────────┴──────────────────────┘
```

### 11.1 상단 Header 영역

포함:

- Breadcrumb
- Category Badge
- 세부 서비스 Badge
- 프로젝트 제목
- 한 줄 요약
- 학교 인증 의뢰자
- 등록 시각
- 조회수(선택)
- 핵심 태그
- 찜
- 공유

대형 이미지/Hero는 기본 구성에서 제외한다.

### 11.2 한눈에 보는 프로젝트

본문을 읽기 전에 거래 조건을 파악하는 영역.

```text
예산           작업 기간       모집 마감       지원자       진행 방식
100,000원      약 7일          D-5             8명          온라인
```

표처럼 조밀하게 만들지 않고 Icon + Label + Value의 4~5개 정보 카드/칸으로 구성한다.

모바일에서는 2열 또는 가로 Scroll.

### 11.3 프로젝트 내용

자유 텍스트.

권장 길이:

- 최소 몇 문장
- 지나치게 긴 글은 문단 간격 유지
- Rich Text는 Bold/목록/링크 수준으로 제한

사용자가 등록한 줄바꿈을 보존한다.

### 11.4 원하는 결과물

수행자가 범위를 판단하는 가장 중요한 Section 중 하나.

예:

```text
✓ A2 사이즈 포스터 1종
✓ SNS 홍보 이미지 1종
✓ 편집 가능한 원본 파일
```

가능하면 Check list 형태.

### 11.5 작업 요청사항

예:

```text
• 밝고 트렌디한 분위기
• 행사명, 날짜, 장소가 잘 보여야 함
• 대학생 대상의 색감과 스타일
• 인쇄/SNS 모두 사용 가능
• 초안 후 1~2회 수정 협의
```

`결과물`과 `요청사항`을 한 Section으로 합치지 않는다.

결과물 = 무엇을 넘겨야 하는지  
요청사항 = 어떻게 만들어야 하는지

### 11.6 필요한 기술 및 도구

Chip:

```text
Figma
Illustrator
Photoshop
그래픽 디자인
포스터 디자인
```

프로젝트 탐색 필터와 동일한 Skill Taxonomy를 사용한다.

### 11.7 일정 안내

```text
모집 마감    2026.10.10   D-5
작업 시작    2026.10.12 예정
완료 희망    2026.10.19 예정
```

날짜가 없는 경우 억지로 빈 필드를 보여주지 않는다.

### 11.8 참고자료

**선택 영역**.

지원:

- 이미지
- PDF
- 문서
- 압축파일
- 외부 링크

표시:

```text
행사 기획안.pdf       PDF · 2.4MB        다운로드
지난해 포스터.jpg     JPG · 1.8MB        미리보기
```

프로젝트 상세을 갤러리 페이지처럼 만들지 않는다.

이미지 첨부가 있더라도 본문 아래 참고자료로 보여주는 것이 기본이다.

### 11.9 의뢰자 정보

최소한의 신뢰 정보만 제공.

```text
이지현  ✓ 백석대학교 인증
디자인영상학부

완료 의뢰 6건
받은 후기 ★ 4.9 (12)
```

다음은 공개하지 않는다.

- 학번
- 직번
- 전화번호
- 이메일
- 개인 연락처

### 11.10 우측 Sticky CTA

가장 중요한 Action만 둔다.

```text
모집중                           D-5

예산
100,000원

[      지원하기      ]
[      문의하기      ]
[ ♡ 프로젝트 저장    ]

✓ 백석대학교 인증 의뢰자
```

규칙:

- 스크롤 시 Sticky
- 카드 안에서 같은 숫자/설명을 과도하게 반복하지 않음
- `지원하기`만 Primary Blue
- 문의/저장은 Secondary
- 마감 상태에 따라 CTA 자동 변경

### 11.11 상태별 화면

#### OPEN

`지원하기` 활성.

#### 이미 지원함

```text
[지원 완료]
[내 지원 내용 보기]
```

#### 본인이 등록한 프로젝트

```text
[지원자 8명 보기]
[프로젝트 수정]
[모집 마감]
```

본인에게 `지원하기`는 보이지 않는다.

#### MATCHED

```text
모집 완료
수행자가 선정된 프로젝트입니다.
```

#### CLOSED

수행자 신규 지원 CTA 비활성 + `모집이 마감되었습니다.`. 소유자는 기존 지원자 검토·선정 가능. 거래 완료 상태와 구분한다.

#### CANCELLED

취소 상태 표시. 일반 추천/탐색에서는 노출하지 않는 것을 기본으로 한다.

### 11.12 이미지 정책

프로젝트 등록자가 대표 이미지를 제작해야 하는 UX는 사용하지 않는다.

목록에서 이미지가 필요한 경우:

```text
첨부 이미지 존재 → 사용 가능한 이미지 Thumbnail
첨부 이미지 없음 → Category Placeholder
```

상세페이지에는 해당 Thumbnail을 다시 큰 Hero로 반복하지 않는다.

### 11.13 모바일

- 한 열
- 상단 제목/조건 압축
- `한눈에 보는 프로젝트` 2열
- Sticky Sidebar 없음
- 하단 고정 CTA:

```text
100,000원                       [지원하기]
```

`문의 / 저장`은 상세 내부 또는 More 메뉴.

### 11.14 프로젝트 등록과의 관계

상세 디자인을 등록자가 직접 만드는 구조가 아니다.

```text
프로젝트 등록 폼
→ 필요한 내용 입력
→ 시스템이 Standard Section으로 자동 배치
→ 상세페이지 생성
```

즉 등록자의 디자인 능력과 무관하게 모든 프로젝트가 같은 수준의 가독성을 가져야 한다.

## 13. 지원자 비교

엑셀처럼 모든 정보를 한 표에 억지로 넣지 않는다.

### 기본 화면

지원자 카드를 세로로 비교하되 다음 정보만 바로 보여준다.

- 대표작
- 전문 분야
- 제안 한마디
- 견적
- 기간
- 완료 작업
- 후기

### 비교 모드

사용자가 2~3명을 선택하면 핵심 항목만 나란히 보여준다.

```text
             김OO          박OO          이OO
대표작        [img]         [img]         [img]
금액          30만          35만          28만
기간          7일           5일           8일
완료          5건           2건           신규
후기          4.9           5.0           -
```

신규 사용자가 과도하게 불리하지 않도록 `완료 건수`는 보조 정보로 취급한다.

## 16. 완료·후기·검증 포트폴리오

작업 완료 후 다음 흐름을 제공한다.

```text
작업 완료
→ 양측 완료 확인
→ 후기 작성
→ 수행자: “이 작업을 포트폴리오에 추가할까요?”
→ 의뢰자에게 공개 확인 요청
→ 승인
→ 프로필에 `✓ 긱창업에서 완료한 작업`으로 표시
```

이 기능은 신규 학생이 실제 학교 프로젝트를 수행하면서 자연스럽게 경력을 쌓게 하는 핵심 장치다.

## 17.4 이미지

### 포트폴리오

- 이미지가 카드 면적의 60~75%를 차지하도록 한다.
- 썸네일 비율은 기본적으로 `4:3`.
- 영상은 동일한 카드 안에서 플레이 아이콘 표시.
- 이미지 없는 포트폴리오는 되도록 만들지 않는다.

### 프로필 사진

- 원형 또는 Rounded Square.
- 작업물보다 크게 노출하지 않는다.
- 전문가 탐색 목록에서는 프로필 사진을 생략할 수 있다.
- 프로필 상세/후기/의뢰자 정보처럼 사람 식별이 필요한 곳에서 보조적으로 사용한다.

### 프로젝트 이미지

- 프로젝트 대표 이미지는 등록 필수가 아니다.
- 프로젝트 목록은 첨부 이미지가 없을 때 Category Placeholder를 사용한다.
- 프로젝트 상세은 이미지보다 텍스트/조건을 우선한다.
- 참고 이미지는 본문 `참고자료`에서 미리보기한다.

## 20. 반드시 피할 디자인

- 전형적인 대학 홈페이지 스타일
- 모든 메뉴를 한 화면에 노출하는 포털형 UI
- 파란색 배경 남용
- 긴 설명을 카드에 그대로 노출
- 작은 글자와 조밀한 표
- 모바일에서 PC 화면을 단순 축소
- 프로필의 첫 화면을 자기소개 글로 채움
- 포트폴리오를 프로필 최하단에 숨김
- 여러 페이지에 동일 정보를 반복 입력하게 함
- 지원 때마다 경력/작업물을 다시 업로드하게 함
- 프로젝트 등록을 위해 대표 이미지/홍보 배너를 반드시 제작하게 함
- 프로젝트 상세을 포트폴리오 상세처럼 대형 이미지 갤러리 중심으로 구성

## 22. 구현 시 최우선 UX 5개

1. **대표 작업물이 프로필 첫 화면에 바로 보인다.**
2. **지원할 때 기존 포트폴리오를 선택해서 붙일 수 있다.**
3. **의뢰자가 작업물 자체를 검색/탐색할 수 있다.**
4. **매칭 후 채팅·계약·파일은 프로젝트 워크룸에서 이어진다.**
5. **완료한 실제 작업이 검증된 포트폴리오 경력으로 쌓인다.**

이 다섯 가지가 구현되면 긱창업은 단순한 교내 구인 게시판이 아니라  
**학생이 실력을 보여주고 실제 경력을 축적하는 교내 긱·포트폴리오 플랫폼**으로 차별화할 수 있다.
