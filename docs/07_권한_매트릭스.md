# 07. 권한 매트릭스

기준일: 2026-10-01 · 상태: **구현 전 권한 정책 제안**

한 사용자가 거래별로 의뢰자·수행자를 겸한다. 전역 EXPERT 역할로 권한을 부여하지 않는다. 프론트 route guard와 allowedActions는 안내용이며 API가 매 요청 객체 권한을 검사한다. 실제 학교 인증 범위·필수 시점은 D-02/D-04 승인 대상이다.

## 1. 표기와 평가 순서

| 기호 | 의미 |
| --- | --- |
| PUBLIC | 공개 상태·제재·삭제 조건을 만족한 데이터만 비회원 포함 열람 |
| ME | 유효 세션의 ACTIVE 계정 |
| V | ME + 유효한 학교 인증 |
| OWNER | 해당 리소스 작성자/소유자 |
| MEMBER | 특정 거래·대화의 당사자, 다른 방 멤버는 포함하지 않음 |
| STAFF | 심사/지원/분쟁/감사/운영 등 해당 범위를 부여받은 운영 계정 |

평가 순서: 세션·계정 → 객체 존재/노출 → 관계 → 학교 인증이 필요한 신규 행동인지 → 상태·버전 → 첨부·하위 객체. 요청 body의 ownerId, subjectId, verified 등은 서버가 유도한다. 거래 ID를 아는 것만으로 관계를 충족하지 않는다.

## 2. 공개·계정·프로필

| 대상/행동 | 허용 대상 | 조건·노출 제한 |
| --- | --- | --- |
| 공개 프로젝트 목록·상세 | PUBLIC | PUBLIC이고 게시된 상태, CANCELLED·DRAFT 제외. 마감/진행 중 여부를 구분 표시 |
| DRAFT 조회·수정 | OWNER+ME | 타인에게 존재 여부도 노출하지 않음 |
| DIRECT_ONLY 조회 | 해당 발신자·수신자 | 공개 탐색·추천·검색에서 제외 |
| 전문가·작업물 조회 | PUBLIC | 공개 프로필/공개 버전, 제재·탈퇴 제외 |
| 내 계정·프로필 편집 | ME | 허용 필드만, 인증·집계는 편집 불가 |
| 학교 인증 신청·조회 | ME | 본인 이력·증빙만 |
| 학교 인증 심사 | 인증 STAFF | 맡은 범위, 사유·감사, 증빙 링크 제한 |
| 포트폴리오 초안·비공개 | OWNER | 공유 동의된 제출 snapshot은 해당 의뢰자 별도 열람 |
| 포트폴리오 공개 | OWNER+V 제안 | 공개 필수값·READY 파일 확인, D-04 결정에 포함 |
| 찜·최근 활동 요약·알림 | ME | 본인 데이터만, 비공개 전환된 대상은 제외 |
| OAuth 연결·해제·탈퇴 | ME+재인증 | 마지막 인증 수단 해제 금지, 다른 계정 이메일 자동 병합 금지 |

PUBLIC 응답에는 이메일·학교 식별번호·증빙·세션·계약 전문이 없다. 공개 API와 별도 개인화 응답을 사용하고 비공개 응답은 no-store다.

## 3. 의뢰·지원·지정 요청

| 행동 | 의뢰자/원래 발신자 | 수행 후보/원래 수신자 | 제3자 |
| --- | --- | --- | --- |
| 공개 의뢰 게시 | OWNER+V | 불가 | 불가 |
| 지원 제출 | 자기 의뢰 불가 | V, OPEN·마감 전 | 다른 사용자 사칭 불가 |
| 지원 목록·비교 | OWNER | 본인 지원만 | 불가 |
| 지원 수정·철회 | 불가 | 작성자, 선정 전 | 불가 |
| 지원 거절 | OWNER | 불가 | 불가 |
| 선정 | OWNER+V | 스스로 선정 불가 | 불가 |
| 모집 마감·선정 전 취소 | OWNER+ME | 불가 | 불가 |
| 지정 요청 생성 | V, 자신에게 요청 금지 | 수신 대상 | 불가 |
| 지정 요청 상세·조건 이력 | 당사자 | 당사자 | 불가 |
| 견적 회신 | 불가 | 원래 수신자+V | 불가 |
| ORIGINAL 수락 | 불가 | 원래 수신자+V | 불가 |
| QUOTE 수락 | 원래 발신자+V | 자기 견적 수락 불가 | 불가 |
| 지정 요청 취소/거절 | 발신자가 취소 | 수신자가 거절 | 불가 |

선정·지정 요청 수락은 양측 ACTIVE·학교 인증 유효 여부를 다시 검사한다는 제안이다. 가입만 한 비공개/수신 불가 프로필로 지정 요청을 보내지 못한다. availability=BUSY는 표시 상태이며 요청을 금지하는 기능과 혼동하지 않는다. 수신 금지가 필요하면 별도 정책·필드를 추가한다.

## 4. 워크룸·계약·완료

| 행동 | 의뢰자 | 선정 수행자 | 기타 지원자/제3자 |
| --- | --- | --- | --- |
| 방 개요·기존 메시지·거래 자료 | MEMBER | MEMBER | 불가 |
| 거래 전 문의 생성 | 해당 공고 소유자와 후보, 또는 지정 요청 당사자만 | V, 공개 공고 OPEN 또는 요청 PENDING | 임의 DM 불가 |
| 기존 대화 전송·읽음 | 해당 대화 MEMBER | 해당 대화 MEMBER | 다른 후보는 자신의 대화만 |
| 워크룸 파일 업로드·연결 | MEMBER, 활성 거래 | MEMBER, 활성 거래 | 불가 |
| 계약 새 버전 생성 | MEMBER | MEMBER | 불가 |
| 계약 버전 발행·철회 | 해당 버전 작성자만 | 해당 버전 작성자만 | 불가 |
| 계약 동의 | 자신의 동의만 | 자신의 동의만 | 대리 동의 불가 |
| 계약 PDF | MEMBER | MEMBER | 불가 |
| 완료 요청·요청 철회 | 불가 | 수행자만 | 불가 |
| 완료 승인·보완 요구 | 의뢰자만 | 불가 | 불가 |
| 거래 취소 합의 요청 | MEMBER | MEMBER | 불가 |
| 취소 합의 승인·거절 | 상대가 요청했을 때 | 상대가 요청했을 때 | 불가 |
| 후기 작성 | 완료 후 수행자에 1회 | 완료 후 의뢰자에 1회 | 불가 |
| 작업 공개 승인 요청 | 불가 | 완료 수행자, 본인 버전만 | 불가 |
| 작업 공개 승인·반려 | 해당 완료 의뢰자 | 자기 승인 불가 | 불가 |

COMPLETED/CANCELLED의 방은 거래 명령·신규 파일 연결을 막고 기록 열람은 유지한다. 기존 대화의 추가 메시지는 분쟁 대응을 위해 허용하는 초기 제안이며 운영 보유 정책에 따른다. 새 계약·완료·취소 명령의 상태 가드는 [04](04_도메인_상태도.md)와 함께 적용한다.

## 5. 파일 권한

| 목적 | 원본 열람자 |
| --- | --- |
| 미연결 업로드 | 업로더만, READY 전 다운로드 불가 |
| 공개 의뢰 참고자료 | 게시 시 공개 공유에 동의한 READY 자료만 PUBLIC; 초안은 소유자 |
| 지원서 첨부·대표작 snapshot | 지원자와 해당 의뢰자 |
| 지정 요청 조건 첨부 | 원래 발신자·수신자 |
| 메시지 파일 | 그 대화 멤버만 |
| 워크룸·완료 산출물·계약 PDF | 해당 거래 당사자만 |
| 학교 증빙 | 본인 및 인증 담당 STAFF |
| 작업물 미디어 | 공개된 버전의 승인된 파생본만 PUBLIC, 비공개 원본은 OWNER |

mediaId만으로 권한을 얻지 않는다. media_links의 대상 관계를 확인한다. 같은 파일을 여러 대상에 연결할 때 공개 범위가 넓어지는 동작은 업로더의 명시적 권한·목적 검사를 요구한다. 서명 URL은 짧게 발급하며 이미 발급한 URL의 즉시 회수를 보장하지 않는다. 보존/폐기는 D-06에 따라 별도로 수행한다.

## 6. 인증 세션과 계정 변화

- 서버 opaque session과 HttpOnly·Secure·SameSite=Lax 쿠키 제안. 운영에서 프론트 저장소의 계정 ID는 인증 수단이 아니다.
- 비회원도 `/auth/csrf`로 사전 인증 세션의 CSRF token을 받는다. 로그인 시 세션 ID와 CSRF token을 회전하고 응답으로 새 token을 반환한다.
- 로그인 유지 미선택은 세션 쿠키, 선택은 만료 쿠키. 서버 idle/absolute 수명은 독립 설정하며 초기 absolute 24시간/7일을 검토안으로 둔다. 실제 수명·idle 값은 운영 승인 전 미확정이다.
- OAuth callback은 state·사전 인증 문맥·만료·일회성 소비를 검사한다. 제공자 신원과 자체 userId를 연결하며 제공자 토큰은 필요한 경우만 서버에서 보관한다.
- next는 허용된 내부 경로와 쿼리만 보존한다. 외부 URL·프로토콜 상대 URL을 거절하면서 `/projects/:id/apply`, `/request/new?expert=:id` 복귀를 지원한다.
- 로그아웃·비밀번호 재설정·정지는 서버 세션을 폐기한다. SSE 연결도 종료하고 프론트 개인 캐시·초안 접근·파일 URL을 정리한다.
- 학교 인증 만료는 신규 게시·지원·문의·매칭을 제한하되 기존 계약 이행 접근을 자동 박탈하지 않는다.
- 정지는 일반 로그인·접근을 차단한다. 진행 거래의 예외 접근은 운영자가 별도 범위와 사유로 처리하며 자동 허용하지 않는다.

## 7. 운영 권한과 거절 기준

인증 STAFF는 증빙, 지원 STAFF는 배정된 문의, 분쟁 STAFF는 사건 관련 자료, 감사 STAFF는 마스킹된 감사 이력, 운영 STAFF는 Job 상태를 다룬다. 관리자라는 이유로 모든 방을 검색·열람하지 못한다. 민감 자료 열람·강제 취소·실패 작업 재처리는 사유·담당 범위·감사를 남긴다.

학교 미인증처럼 본인에게 설명 가능한 제한은 403과 기계 판독 code, 타인 비공개 객체는 404로 처리한다. 과거 권한으로 받은 download URL·SSE·cached DTO의 수명도 함께 관리한다. A/B/C 계정으로 경로 ID·첨부 ID·견적 ID를 바꾸는 테스트와 로그아웃 후 세션 재사용 테스트를 필수로 둔다.
