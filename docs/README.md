## 백엔드 구현 반영 (2026-10-01)

사용자 구현 요청에 따라 `backend/`에 NestJS·TypeScript·PostgreSQL API와 Worker를 추가했다. [실행·구조·검증 및 설계 차이](../backend/README.md), [생성 OpenAPI](../backend/contracts/openapi.json), [DB migration](../backend/migrations/001_core.sql), [HTTP 통합 테스트](../backend/tests/api.test.ts)를 현재 구현 증거로 사용한다. 아래 번호 문서는 구현 직전의 목표 설계를 보존한 것이다. 기존 본문의 “백엔드 미구현” 표기는 당시 상태이며 현재 서버 범위는 백엔드 README를 우선한다. 프론트 API 연결·외부 서비스 실연동·운영 배포 완료를 뜻하지 않는다.

표시 규칙:

- **현재 구현**: 소스에서 확인한 프론트엔드 동작. 운영 기능 완료를 의미하지 않는다.
- **확정 요구**: 사용자와 합의했거나 기존 서비스 범위에 명시된 요구. 코드 구현 여부는 별도다.
- **설계 제안**: 백엔드 구현을 위한 기본안. 기술·운영 책임자의 승인 전 확정 사항으로 취급하지 않는다.
- **디자인 대기**: 사용자가 시안을 먼저 준비하는 범위. 화면 구조를 임의로 확정하거나 구현하지 않는다.
- 기존 두 문서의 본문은 목표 서비스 명세를 포함한다. 구현 여부는 아래 표가 기준이고, v2 변경 사항은 과거 시안 예시보다 우선한다. 상세 상태 전이와 API는 새 04·06 문서를 기준으로 검토하며, 기존 데이터·API 계약은 이전 초안으로 보존한다.

문서 정비에서는 백엔드·DB·배포 환경을 구현하지 않았다. 이후 추가 요청에 따라 로그인/회원가입 시안을 반영했으며, 그 변경 및 소셜 인증 미연결 상태는 별도 적용 기록에서 확인한다.

## 2. 변경하지 않는 서비스 범위

1. 한 계정이 의뢰자·수행자로 모두 활동한다. 가입 시 두 계정 유형으로 영구 분리하지 않는다.
2. 공개 의뢰에 지원하거나, 전문가/작업물에서 지정 요청으로 시작하는 두 경로를 지원한다.
3. 매칭 뒤 메시지·계약·파일·완료 확인을 프로젝트 워크룸에 모은다.
4. 프로젝트 상세는 업무 조건 중심, 전문가/작업물은 대표 결과물 중심이다.
5. 결제·PG·에스크로·정산·환불·외부 전자서명은 1차 범위 밖이다. 합의 금액은 결제 완료의 증거가 아니다.
6. 포트폴리오 **등록/수정 화면은 사용자 디자인 대기**. 데이터 모델·API 초안은 준비하되 편집기 레이아웃·블록 종류·업로드 순서를 확정하지 않는다.

## 4. 현재 데모를 운영 설계로 오해하지 않기

- `bu-gig:*` localStorage의 프로젝트·지원·찜·메시지·파일은 사용자별로 격리되지 않는다. 폼의 `ownerId: "me"`와 고정 표시명은 실제 계정 식별자가 아니다.
- 데모 계정은 이름·이메일·솔트·PBKDF2 파생 해시를 localStorage에 저장하고, 계정 ID를 sessionStorage에 보관한다. 원문 비밀번호를 저장하지 않더라도 서버 인증·권한 검사가 되는 것은 아니다.
- 신규 인증 시안 반영 후 ‘로그인 상태 유지’ opt-in은 로컬 ID·7일 만료 시각도 저장한다. 소셜 로그인 버튼은 준비 중 안내만 제공하며 실제 OAuth는 미연결이다.
- `verified`, 완료 건수, 평점, 후기 등은 대부분 seed 데이터다. 신규 가입은 학교 인증을 부여하지 않는다.
- 프론트 필터 `verified`는 현재 명시적 false만 제외한다. 운영에서는 서버가 검증한 true만 통과시켜야 한다.
- 예산 직접 입력은 구간 겹침으로 검색하지만 기존 프리셋은 프로젝트 최소 금액 기준이다. 운영 연동 시 하나의 구간 규칙으로 통일할 작업이 남았다.
- 마감 시각·접근 권한·선정·계약 체결의 최종 판단은 프론트 코드나 localStorage가 아니라 서버가 담당해야 한다.
- 기존 자산은 프로토타입용 크롭이다. 운영 라이선스·품질·접근성 대체 텍스트를 확인한다.

## 6. 결정이 필요한 사항

백엔드 언어·프레임워크, 배포 사업자, 예상 동시 접속, 학교 SSO/이메일 도메인·인증 방식, 개인정보 보유 기간, 계약 운영 정책은 아직 확정되지 않았다. [개발·검증 계획](개발_검증_계획.md)의 결정 목록을 승인한 뒤 구현에 착수한다. 자료에 없는 학교 도메인·운영 조직·법적 효력을 임의로 확정하지 않는다.
